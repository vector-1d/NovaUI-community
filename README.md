# NovaUI for Unity

NovaUI is a comprehensive, open-source UI framework for Unity that simplifies UI development and enhances the performance and aesthetics of your projects. This repository contains the full source code for NovaUI—available for free—and serves as a community hub for fixes, new features, and templates.

> **Important:** NovaUI is designed for **Unity v6 and above**. Please ensure you are using Unity version 6.0 or later to take full advantage of all features and improvements.

## Features

- **Rich UI Components:** A complete set of modern and responsive UI elements.
- **Performance Optimized:** Designed with performance in mind for both mobile and desktop platforms.
- **Intuitive API:** Easy-to-use interfaces and robust documentation to speed up development.
- **Fully Customizable:** Extend and tailor components to fit your project requirements.
- **Community-Driven:** Collaborate with other developers to improve and expand NovaUI with community contributions.

## Getting Started

### Prerequisites

- **Unity:** Version **v6.0 or later**.
- **Git:** For cloning and managing the repository.
- (Optional) Familiarity with C# and Unity’s UI system.

### Installation

1. **Clone the Repository:**

   ```bash
   git clone https://github.com/vector-1d/NovaUI-community.git
   ```

2. **Open in Unity:**
   - Launch Unity Hub.
   - Click on **"Open Project"** and select the cloned repository folder.

3. **Set Up Your Project:**
   - Ensure all required packages are imported.
   - Navigate to the `Docs` folder for additional setup and configuration instructions.

### Running the Examples

NovaUI comes with several example scenes that demonstrate its features:

1. Open any scene from the `Assets/NovaUI/Examples` directory.
2. Press **Play** to see NovaUI in action.

## Community Contributions

We encourage contributions from the community! If you have ideas for new features, bug fixes, or additional templates, please follow these steps:

1. **Fork** the repository.
2. **Create a Feature Branch:**  
   Use descriptive branch names, e.g., `feature/new-component` or `bugfix/fix-layout-issue`.
3. **Make Your Changes:**  
   Ensure your code is well-documented and tested.
4. **Submit a Pull Request:**  
   Include a clear description of your changes and reference any related issues.
